🏭 LLaMA Factory 完整指南 (v0.9+)

LLaMA Factory 是由 hiyouga 开发的统一高效微调框架，支持 100+ 模型、50+ 数据集，支持 LoRA/QLoRA/全参数微调、DPO/ORPO/SimPO 对齐训练、多机分布式训练。

# 安装 LLaMA Factory
pip install llama-factory[all]
# 启动 Web UI (推荐)
llamafactory-cli webui
# 命令行训练示例
llamafactory-cli train examples/train_lora/qwen_lora_sft.yaml
# 多卡训练 (DeepSpeed ZeRO-3)
FORCE_TORCHRUN=1 llamafactory-cli train examples/train_lora/qwen_lora_sft_ds.yaml
# Ray 分布式训练 (4 GPU)
USE_RAY=1 llamafactory-cli train examples/train_lora/qwen_lora_sft_ray.yaml
🎯 YAML 核心配置参数详解:
参数推荐值说明
finetuning_typelora / qlora / full微调类型
lora_rank (r)8-64 (默认16)秩大小，↑能力 ↑显存
lora_alphar × 2 (如32)缩放因子 = alpha/r
lora_targetall / qkv目标层: q/k/v/o/gate/up/down_proj
lora_dropout0.05-0.1Dropout防止过拟合
learning_rate1e-4 ~ 5e-4学习率
num_train_epochs3-10训练轮数
per_device_train_batch_size1-4每GPU批次大小
gradient_accumulation_steps4-8梯度累积等效增大batch
quantization_bit4/8 (QLoRA)量化位数(Bitsandbytes)
cutoff_len512-2048输入截断长度

📚 LoRA 变体对比 (2025 最新基准)

🔹 LoRA (原始)Hu et al., ICLR 2022

通过低秩矩阵分解 W₀ + BA 注入适配器权重。可训练参数仅占原模型的 0.1%-1%，在多数任务上达到全量微调 99% 性能。

LLaMA3-8B 基准: MMLU 80.8% | 可训练参数 0.70% | 显存 ~16GB
✅ 行业标准 ✅ HuggingFace PEFT原生支持 ⚡ 中等显存需求
🔹 QLoRA (量化LoRA)Dettmers et al., 2023

结合 4-bit NF4/FP4 量化 + 双重量化(Double Quantization) + LoRA。可在单张24GB显卡微调65B模型，精度损失仅1-2%。

性能数据: 相比基线提升 10-20pt | QLoRA仅比LoRA低 2-4pt | 显存降低 >90%
✅ 消费级显卡友好 ✅ 大模型(70B+)首选 ⚠️ 推理需反量化合并
🔹 AdaLoRA (自适应)Zhang et al., 2023

通过重要性评分动态分配各层的秩(rank budget)。重要层获得更高秩，不重要层降秩甚至跳过。

核心创新: SVD-based importance score | 正交正则约束 | 总参数量与LoRA相当但分配更优
✅ 自动优化秩分配 ✅ 参数效率更高 ⚠️ 训练开销增加~30%
🔹 DoRA (权重分解)Liu et al., ICLR 2024

将预训练权重分解为幅度(magnitude)和方向(direction)，分别学习更新。解决LoRA中幅度和方向的耦合问题。

关键优势: 方向学习保持低秩 | 幅度学习可全量 | 数学上等价于LoRA但优化空间更大
✅ 接近全量微调性能 ✅ 数学理论优雅 ⚠️ 参数量略高于LoRA
🔹 DenseLoRA (2025新)ACL 2025

密集型低秩适应方法，通过分组(grouped)和共享(shared)策略实现极低参数量下的高性能微调。

突破性结果: LLaMA3-8B 准确率 83.8%(vs LoRA 80.8%) | 可训练参数仅 0.01%(vs LoRA 0.70%) | 效率提升 70x
🆕 极致参数效率 🆕 性能超越LoRA ⚡ 较新方法待广泛验证

💡 最佳实践 & 专业建议

🎯 数据工程
  • 质量优先: 1000条高质量 > 10万条噪声数据
  • 指令格式: 使用 Alpaca/ShareGPT 标准格式
  • 多样性: 覆盖目标任务的各种变体
  • 去重去噪: 使用 MinHash/SimHash 去重
  • 验证集: 至少保留 5%-10% 用于评估
⚙️ 训练调优
  • Warmup: 前 3-10% steps 学习率线性预热
  • Cosine LR: 余弦退火调度器效果最佳
  • Early Stopping: 验证集 loss 不降则停
  • Gradient Checkpointing: 节省 ~30% 显存
  • Mixed Precision: BF16/BF16+fp16 混合精度

📖 工作流编排指南

🏗️ 架构设计 (参考 n8n/LangFlow)

辉夜工作流引擎采用有向无环图(DAG)架构，支持10种节点类型，可构建从简单对话到复杂Agent系统的各类AI应用。

🤖 AI 节点
  • LLM: 大模型推理，支持流式输出
  • MCP: 工具调用，知识库检索
🔀 控制流
  • 条件: IF/ELSE 分支路由
  • 循环: 迭代执行子流程
  • 延迟: 等待/定时触发
💻 数据处理
  • 代码: Python 脚本执行
  • HTTP: REST API 调用
  • 转换: JSON/文本数据转换
📡 生命周期
  • 开始: 工作流入口点
  • 结束: 输出结果/终止

🎯 典型工作流模式

💬 单轮对话 (Simple Chat)
开始 → LLM → 结束 | 适用于简单问答、翻译、摘要
📚 RAG 检索增强 (Retrieval Augmented)
开始 → 知识库检索 → LLM(含上下文) → 结束 | 适用于文档问答、知识库查询
🤖 ReAct Agent (推理+行动)
开始 → LLM → 条件(是否调用工具) → MCP工具/直接输出 → 结束 | 适用于多步推理
🔗 数据管线 (ETL Pipeline)
开始 → HTTP请求 → 数据转换 → 条件过滤 → LLM分析 → 结束 | 适用于数据处理、API编排
📌 操作指南
  • 从左侧面板拖拽节点到画布
  • 点击节点输出端口(黄色)拖拽到另一节点输入端口(绿色)创建连线

📖 RAG 技术教程

🏗️ 一、RAG 架构演进

RAG (Retrieval-Augmented Generation) 通过检索外部知识来增强 LLM 的生成能力，解决幻觉和知识过时问题。

Naive RAG (朴素)
用户查询 → 向量检索 → Top-K 文档 → 拼接 Prompt → LLM 生成
问题：检索质量不稳定、缺乏查询理解、噪声文档直接传入 LLM
Advanced RAG (高级)
查询改写 → 混合检索(向量+关键词) → 重排序+压缩 → LLM 生成(带校验)
优化点：Pre-retrieval 改写/扩展 | Retrieval 混合搜索 | Post-retrieval 重排/过滤
Modular RAG (模块化) ← 2024 主流
将 RAG 解耦为可插拔模块：索引模块 | 检索模块 | 重排模块 | 编排模块 | 生成模块 | 评估模块
支持动态路由、迭代检索-生成循环、Agent 自主决策

🧩 二、核心组件详解

📄 文档加载
  • Unstructured - 最全面，支持 PDF/HTML/PPT/DOCX/OCR
  • Docling (IBM, 2024) - 结构化解析强，新秀
  • PyMuPDF - 速度快，保留表格
  • LlamaParse - LlamaIndex 生态
最佳实践：保留文档层级结构(标题/段落/表格)作为元数据
✂️ 分块策略 (关键瓶颈!)
  • 固定大小 - 简单但可能切断语义
  • 递归字符 - LangChain 默认，按分隔符优先级切分
  • 语义分块 - 嵌入相似度断点检测，完整性最好
  • 文档结构 - 按标题层级(H1/H2/H3)切分
经验：分块策略比嵌入模型更重要！推荐 chunk_size=512, overlap=50
🔢 嵌入模型 (2024-2025)
  • bge-m3 (BAAI) - 多语言，dense+sparse+ColBERT 三合一
  • GTE-Qwen2 (Alibaba) - 中英文均强，8192 token
  • NV-Embed-v2 (NVIDIA) - MTEB 第一
  • OpenAI text-embedding-3 - 商用首选
中文场景推荐：bge-m3 或 GTE-Qwen2
🗄️ 向量数据库
  • Milvus/Zilliz - 分布式，十亿级
  • Qdrant - Rust 实现，过滤强
  • Chroma - 轻量，原型首选
  • pgvector - 已有 PG 基础设施时
2024 趋势：混合搜索(向量+BM25)成为标配

🔍 三、检索方法与重排序

稠密检索
Query → Embedding → Cosine Similarity → Top-K。语义理解强，但精确匹配弱。
稀疏检索
BM25 关键词匹配 / SPLADE 学习型稀疏表示。精确匹配强，但语义弱。
混合检索 ★
向量 + BM25 联合检索，RRF 融合排序。2024 主流方案，几乎总是优于纯向量搜索。
重排序 ★
初检索 Top-100 → Cross-encoder 重排 → Top-10。性价比最高的优化！推荐 bge-reranker-v2-m3。
RRF 融合公式：RRF_score(d) = Σ 1/(k + rank_i(d))，k 通常取 60
Alpha 调参：语义查询为主 → 0.7-0.8 | 精确匹配为主 → 0.2-0.3 | 均衡 → 0.5

🚀 四、高级技术

🔄 查询变换
  • 查询改写 - LLM 改写模糊查询为精确查询
  • HyDE - 生成假设性答案，用答案嵌入去检索
  • 查询分解 - 复杂问题拆分为多个子问题
  • Multi-Query - 生成多个查询变体，合并结果
  • Step-back - 先检索更广泛概念，再回答具体问题
🎯 上下文优化
  • 父子检索 - 小块检索，返回父块完整上下文
  • 句窗口 - 检索单句，返回前后 N 句
  • 上下文压缩 - LLM 压缩冗余文档
  • MMR 去重 - 最大边际相关性，减少冗余
  • 元数据过滤 - 按来源/日期/类型过滤
🤖 Agentic RAG (2024 前沿)
  • Self-RAG - 自我反思：相关性/事实性/完整性检查
  • CRAG - 纠错：检索质量差时切换 Web 搜索
  • Adaptive RAG - 动态决定是否需要检索
  • Graph RAG - 知识图谱 + 向量联合检索
🖼️ 多模态 RAG
  • 方案A - OCR/VLM 提取文字 → 纯文本 RAG
  • 方案B - 多模态嵌入(CLIP) → 多模态检索
  • 方案C ★ - VLM 生成描述 + 分别存储 → 混合检索

⚠️ 五、常见陷阱与解决方案

检索不相关Top-K 返回无关文档混合检索 + 重排序 + 相关性阈值
上下文溢出检索文档超出 LLM 上下文上下文压缩、摘要、动态选择
信息丢失分块切断关键信息父子检索、句窗口、重叠分块
幻觉LLM 编造不存在的信息引用追踪、忠实度校验、Grounding
查询理解差用户查询模糊或歧义查询改写、HyDE、多查询

📊 六、评估体系

RAG 评估需分层进行：检索层 → 生成层 → 端到端
RAGAS 框架 (最主流)
  • Faithfulness - 生成是否忠实于上下文
  • Answer Relevancy - 回答是否切题
  • Context Precision - 检索文档中有多少相关
  • Context Recall - 所需信息是否都被检索到
评估最佳实践
  • 建立黄金测试集 (50-200 Q&A 对)
  • 自动评估 + 人工评估结合
  • 每次变更后重新评估
  • 线上 A/B 测试对比策略
